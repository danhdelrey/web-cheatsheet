01 · Đọc trước

Mental model: CSS khác Flutter/Compose thế nào

Phần lớn sự khó chịu với CSS đến từ việc mang mô hình "widget tự mang style, cha đặt kích thước cho con" sang một hệ thống mà style chảy từ nhiều nguồn và layout mặc định là dòng chữ.

Cascade: style đến từ nhiều nơi

Trong Flutter, style là tham số bạn truyền thẳng vào widget. Trong CSS, nhiều rule ở nhiều file cùng nhắm vào một phần tử, và trình duyệt chọn giá trị thắng cho từng property riêng lẻ theo thứ tự: nguồn & !important → @layer → specificity → thứ tự xuất hiện.

/* Bốn rule cùng nhắm vào <button class="btn"> nằm trong .toolbar */
button        { color: black; padding: 8px; } /* 0-0-1 */
.btn          { color: blue; }                 /* 0-1-0: thắng button */
.toolbar .btn { color: green; }                /* 0-2-0: thắng .btn */
.btn          { color: red; }                  /* 0-1-0: viết sau nhưng vẫn THUA .toolbar .btn */

/* Kết quả: color: green; padding: 8px
   (padding không bị rule nào ghi đè nên vẫn lấy từ rule đầu) */
📱 Flutter / Compose

Flutter: Text(style: TextStyle(…)) gắn style chặt vào widget; chỉ DefaultTextStyle/Theme là "chảy" xuống. Compose: thứ tự Modifier tạo ra các lớp lồng nhau (padding trước hay sau background cho kết quả khác). CSS không có chuỗi modifier: thứ tự property trong một rule không tạo lớp, chỉ property trùng tên viết sau ghi đè property trước.

⚠️ Lưu ý

Mỗi property được tính riêng. Một rule có thể thắng color mà không đụng tới padding. Khi style không như ý, mở DevTools → Computed để xem giá trị cuối đến từ rule nào.

Inheritance: chỉ nhóm chữ mới chảy xuống

Một số property tự truyền từ cha xuống mọi con cháu: chủ yếu nhóm chữ (color, font-*, line-height, text-align) cùng visibility, cursor. Nhóm hình học và trang trí (margin, padding, border, background, width, display) không kế thừa.

.card {
  color: #334155;           /* kế thừa: mọi chữ bên trong có màu này */
  font: 15px/1.5 system-ui; /* kế thừa */
  padding: 16px;            /* KHÔNG kế thừa: chỉ .card có padding */
  border: 1px solid #ddd;   /* KHÔNG kế thừa */
}
📱 Flutter / Compose

Giống DefaultTextStyle / IconTheme trong Flutter và LocalContentColor / LocalTextStyle trong Compose: chỉ thuộc tính về chữ chảy xuống cây.

⚠️ Lưu ý

Form control (button, input, select) không kế thừa font theo mặc định. Luôn có font: inherit trong reset.

Normal flow thay cho "constraints go down"

Không có Row/Column ngầm. Mặc định phần tử nằm trong normal flow: block xếp dọc và lấp đầy chiều ngang của cha; inline chảy trên dòng như chữ. Chiều ngang đi từ cha xuống, chiều cao đi từ nội dung lên.

📱 Flutter / Compose

Flutter: "constraints go down, sizes go up, parent sets position". CSS giống ở trục ngang: block có width: auto lấp đầy cha (như constraint chặt theo chiều ngang). Trục dọc thì khác: chiều cao mặc định là "wrap content", cha không ép chiều cao xuống con.

⚠️ Lưu ý

Vì chiều cao đi từ dưới lên, height: 100% chỉ hoạt động khi cha có chiều cao xác định. Muốn con lấp đầy chiều cao, cho cha display: flex/grid (con tự stretch) hoặc dùng flex: 1, tương tự Expanded.

User-agent styles và reset tối thiểu

Trình duyệt có sẵn stylesheet mặc định: body có margin 8px, h1 to và có margin, ul có padding, button có font riêng. Hầu như dự án nào cũng bắt đầu bằng một reset nhỏ như sau.

*, *::before, *::after { box-sizing: border-box; } /* width tính cả padding + border */
body { margin: 0; min-height: 100dvh; }
h1, h2, h3, h4, p, ul, ol, figure { margin: 0; }
ul[role="list"], ol[role="list"] { list-style: none; padding: 0; }
img, svg, video, canvas { display: block; max-width: 100%; } /* bỏ khe hở dưới ảnh inline */
button, input, select, textarea { font: inherit; color: inherit; }
:where(h1, h2, h3) { text-wrap: balance; line-height: 1.2; }
📱 Flutter / Compose

Gần với việc đặt ThemeData/MaterialTheme gốc cho toàn app, khác ở chỗ ở đây bạn đang gỡ mặc định của trình duyệt chứ không chỉ khai báo theme.

Margin collapse

Margin dọc của hai block liền kề không cộng lại mà gộp thành giá trị lớn hơn. Margin-top của con đầu tiên còn có thể "lọt" ra ngoài cha nếu cha không có padding hoặc border.

.a { margin-bottom: 24px; }
.b { margin-top: 16px; }   /* khoảng cách thật giữa .a và .b = 24px, không phải 40px */

/* Cách tránh: dùng gap. Margin collapse không xảy ra trong flex/grid */
.stack { display: flex; flex-direction: column; gap: 16px; }
📱 Flutter / Compose

SizedBox(height: 24) + SizedBox(height: 16) trong Column luôn ra 40. Margin CSS không hành xử như SizedBox; gap thì có (giống Column(spacing:) / Arrangement.spacedBy).

⚠️ Lưu ý

Chỉ margin dọc trong normal flow mới collapse. Margin ngang, flex/grid item, phần tử absolute thì không. Cha có display: flow-root, padding hoặc border sẽ chặn margin của con lọt ra ngoài.

.a .b (có dấu cách) và .a.b (không dấu cách) khác hẳn nhau: một là con cháu, một là cùng phần tử có cả hai class.

Pseudo-class: state và vị trí

Chọn phần tử theo trạng thái hoặc vị trí trong cây. Đây là cách CSS biểu diễn state, không cần biến isHovered.

.btn:hover          { background: #0f766e; }        /* chuột đang trỏ */
.btn:focus-visible  { outline: 2px solid; }         /* focus bằng bàn phím */
.btn:active         { transform: translateY(1px); } /* đang nhấn */
.btn:disabled       { opacity: .5; }
input:checked + label { font-weight: 600; }
input:user-invalid  { border-color: crimson; }      /* chỉ báo lỗi sau khi người dùng đã nhập */

li:first-child, li:last-child { }
li:nth-child(odd)   { background: #f6f6f6; }        /* zebra; cũng có 2n, 3n+1, -n+3 */
li:not(:last-child) { border-bottom: 1px solid #eee; }

:is(h1, h2, h3) a   { color: inherit; }   /* gom selector; specificity = đối số cao nhất */
:where(ul, ol)      { padding-left: 1.25em; } /* như :is nhưng specificity = 0 */
.card:has(img)      { padding-top: 0; }   /* "parent selector": card CÓ chứa img */
📱 Flutter / Compose

Flutter: WidgetStateProperty.resolveWith((states) => states.contains(WidgetState.hovered) ? … : …). Compose: interactionSource.collectIsHoveredAsState(), collectIsPressedAsState(). Trong CSS trình duyệt tự theo dõi state; bạn chỉ khai báo style cho từng state.

⚠️ Lưu ý

Dùng :focus-visible thay cho :focus để vẽ focus ring: người dùng bàn phím vẫn thấy, người click chuột không bị khung thừa. Không bao giờ outline: none mà không có thay thế.

Pseudo-element: ::before, ::after

Tạo "phần tử ảo" để trang trí mà không thêm HTML. Ngoài ra còn ::placeholder, ::selection, ::marker, ::backdrop.

/* Dấu * đỏ cho label bắt buộc */

  content: " *";         /* BẮT BUỘC có content, kể cả content: "" */

.hero { position: relative; }

  content: "";

  inset: 0;
  background: linear-gradient(transparent, rgb(0 0 0 / .6));
}

📱 Flutter / Compose

Giống thêm một con trang trí vào Stack/Box (một Container gradient phủ lên) mà không phải sửa cây widget.

⚠️ Lưu ý

::before/::after không hoạt động trên phần tử "replaced" như img, input, video. Quy ước: hai chấm :: cho pseudo-element, một chấm : cho pseudo-class.

⚠️ Lưu ý

Giữ specificity thấp và phẳng: mỗi rule một class (kiểu BEM hoặc utility). Tránh ID trong CSS; một khi đã dùng, chỉ ID khác hoặc !important mới ghi đè được.

!important và @layer

!important đẩy một khai báo lên trên mọi specificity thường. @layer là cách sạch hơn: chia CSS thành các tầng có thứ tự ưu tiên rõ ràng, tầng sau thắng tầng trước bất kể specificity.

/* Khai báo thứ tự một lần: tầng sau ưu tiên cao hơn */
@layer reset, base, components, utilities;

@layer base {
  #main a { color: navy; }       /* specificity 1-0-1 ... */
}
@layer utilities {
  .text-muted { color: gray; }   /* ... nhưng vẫn THUA rule này vì layer sau thắng */
}

/* CSS nằm ngoài mọi layer thắng tất cả layer */
.special { color: crimson; }

/* Bọc CSS thư viện vào layer thấp để dễ ghi đè */
@import url("vendor.css") layer(vendor);

/* !important: chỉ cho utility hoặc ghi đè inline style của thư viện */
.hidden { display: none !important; }
📱 Flutter / Compose

Không có tương đương trực tiếp. Gần giống Theme lồng nhau: theme gần widget hơn thắng, bất kể nó định nghĩa "cụ thể" đến đâu.

⚠️ Lưu ý

Với !important, thứ tự layer bị đảo: khai báo important ở layer đầu thắng. CSS không thuộc layer nào (ví dụ CSS thư viện cũ) sẽ đè hết CSS có layer của bạn.

03

Box model & đơn vị

Mọi phần tử là một hộp. Phần lớn lỗi "lệch vài pixel" đến từ box-sizing và đơn vị.

content → padding → border → margin

Bốn lớp từ trong ra ngoài: content, padding (trong viền, có nền), border, margin (ngoài viền, trong suốt). Luôn bật box-sizing: border-box để width đã gồm padding và border.

/* Shorthand 4 giá trị theo chiều kim đồng hồ: top right bottom left */

📱 Flutter / Compose

Flutter: Container(margin:, padding:, decoration: BoxDecoration(border:)) gần như 1:1. Compose không có margin: Modifier.padding(24.dp).border(…).padding(16.dp), padding đặt trước border đóng vai margin. Khác biệt: margin CSS có thể âm và có thể là auto; EdgeInsets thì không.

⚠️ Lưu ý

Mặc định là content-box: width 200 + padding 48 + border 4 = hộp rộng 252px. Padding tính theo % luôn dựa trên chiều rộng của cha, kể cả padding-top.

Offstage của Flutter (vẫn layout, không vẽ, không chiếm chỗ, giữ state) gần display: none về hiển thị. CSS không có "state của widget": phần tử bị ẩn vẫn nằm trong DOM, giá trị input vẫn còn, nên mọi cách ẩn trong CSS đều "giữ state".

⚠️ Lưu ý

opacity: 0 vẫn nhận click và vẫn focus được bằng Tab, dễ tạo "nút vô hình". Kết hợp với visibility: hidden (animate được cùng opacity) hoặc thuộc tính inert. *Animate display được với transition-behavior: allow-discrete, xem mục 13.

⚠️ Lưu ý

Implicit animation (transition) cho thay đổi state, explicit animation (@keyframes) cho chuyển động lặp hoặc có kịch bản.

📱 Flutter / Compose

Transform.translate/scale/rotate và Modifier.graphicsLayer { translationY; scaleX; rotationZ }. Giống ở chỗ không ảnh hưởng layout của anh em. Khác: CSS dùng độ (deg, turn), Flutter dùng radian.

⚠️ Lưu ý

⚠️ Lưu ý

Không transition thẳng tới height: auto hay từ display: none; dùng mẹo grid ở trên hoặc @starting-style (bên dưới). Tránh transition: all, dễ animate nhầm thứ không muốn.

⚠️ Lưu ý

⚠️ Lưu ý

Những property quyết định phần tử nhận chạm, nhận focus thế nào. Material lo phần này giúp bạn trên mobile; trên web thì không.
